Explore structure–activity relationships (SAR)

Use public bioactivity data to find chemical series, compare potency, and identify which structural changes may be worth testing.

You needA protein target name or ID. A known active compound is helpful but not essential.
UseChEMBL ↗ and DataWarrior ↗
Time-saving tipBegin with one target and one activity endpoint, not every assay at once.
  1. Confirm the target in ChEMBL.

    Open ChEMBL and search the target name or a stable identifier. Open the target record and check organism, target type, and isoform/construct where available. Do not combine human and non-human targets or different isoforms without a reason.

  2. Open its bioactivity records and filter to comparable measurements.

    Choose one endpoint for the first pass—usually IC50 or Ki, not both. Keep a consistent relation (start with exact values), units, assay IDs, target ID, and compound IDs. Export the table. If the export does not contain structures or SMILES, obtain the structure data for those compound IDs before doing structure-based analysis.

  3. Open the data in DataWarrior.

    Use File → Open to load the CSV or SDF. If there is a SMILES column, DataWarrior can recognize it and create structure and descriptor columns. Check a few rows manually to ensure each structure matches its compound ID.

  4. Compare activity with structures and properties.

    Sort/filter the activity column, inspect the structure view, and create a scatter plot against a property such as molecular weight or calculated lipophilicity. Group related compounds by scaffold and compare substitutions within each series. Treat apparent trends as hypotheses, not proof of causation.

  5. Save an analysis another chemist can reopen.

    Save the complete DataWarrior project as .dwar, then export the shortlisted compounds and table with IDs and source metadata retained.

Save as your result

A curated activity table, a DataWarrior project, and a short list of SAR observations with supporting compound IDs.

Check before concluding

Do the compounds share the same target context, assay endpoint, units, and comparable test conditions? Are censored values such as “>” or “<” being treated correctly?

Compare physicochemical and ADMET risks

Run the same compounds through web predictors, compare the results side by side, and choose which risks need experiments.

You needOne SMILES string and a unique compound ID per molecule. Standardize structures first.
UseSwissADME ↗ and ADMETlab 3.0 ↗
Batch sizeStart with 5–20 compounds and confirm the results before scaling up.
  1. Prepare the input list.

    Make a two-column master sheet with your compound ID and SMILES. Check salts, stereochemistry, charge, and duplicates. Keep the ID unchanged across every tool so the outputs can be joined later.

  2. Run SwissADME.

    Paste one molecule per line in the SMILES field; add a short compound name after each SMILES, separated by a space. Click Run. Save the full output and record the input list. Review descriptors, lipophilicity estimates, solubility estimates, and any absorption or blood–brain barrier indicators relevant to your project.

  3. Run selected endpoints in ADMETlab 3.0.

    Submit the same standardized structures. Select only the endpoints you need for the decision—for example, metabolic stability, CYP-related risk, or toxicity estimates. Export or copy the raw predictions with compound IDs and endpoint names.

  4. Build a comparison table.

    Join results by compound ID. Keep each model's output in its own column; do not average together scores that represent different endpoints. Highlight agreement, disagreement, missing predictions, and compounds outside a model's stated applicability domain.

  5. Turn a prediction into the next experiment.

    For each important risk, state what would confirm it experimentally—for example, solubility, permeability, microsomal stability, or a focused safety assay. Rank experiments by how much uncertainty they would remove.

Save as your result

A compound-by-property table with model names, raw predictions, source date, uncertainties, and proposed experimental follow-up.

Check before concluding

Predictions are not measurements. A favourable rule-of-thumb, lipophilicity, or single “BBB” output does not establish brain exposure or overall developability.

Inspect a protein–ligand complex

Combine a visual inspection with an interaction report to check whether a proposed binding pose makes chemical sense.

You needA protein–ligand complex file from an experimental structure or a saved docking pose. A protein file alone is not enough for ligand-contact analysis.
UsePyMOL ↗ and PLIP web server ↗
DifficultyBeginner-friendly once you have the complex file in a supported format.
  1. Start with a trustworthy complex.

    For an experimental complex, find the structure in the Protein Data Bank and download the coordinate file containing the bound ligand. Note the PDB ID, chain, ligand residue name, and any important cofactors. For a docked pose, keep the receptor and selected ligand pose together and convert to a PLIP-compatible complex file if necessary.

  2. Generate an interaction report in PLIP.

    Open the PLIP web service, upload the complex, and run the analysis. Save the report and the input file. Check that PLIP identified the intended ligand and protein chain—not a crystallization additive or the wrong small molecule.

  3. Inspect the same pose in PyMOL.

    Open the complex in PyMOL. Display the protein as a cartoon, the ligand as sticks, and the pocket residues as sticks or labelled side chains. Focus on the interactions that matter to the design hypothesis rather than labelling every contact.

  4. Check the chemistry behind the reported contacts.

    For important hydrogen bonds, check donor/acceptor identity and geometry. Look for clashes, unsupported protonation assumptions, missing waters, and contacts to residues that may not belong to the relevant binding site.

  5. Translate the observation into a testable idea.

    Compare the pose with known ligands or a close analogue. Write down one proposed structural change and what assay result would support or refute the hypothesis.

Save as your result

The original complex, PLIP report, PyMOL session, an annotated image, and a short note linking each design idea to a specific contact.

Check before concluding

A contact report does not prove binding or rank affinity. The quality of the result depends on the input structure, ligand identity, protonation, and biological context.

Dock a ligand into a protein with AutoDock Vina

A reproducible starter route for a single ligand. The first setup involves command-line tools; after that, the same steps can be repeated across a small series.

You needA protein structure, a ligand structure with correct stereochemistry, and a defined binding site. Use a co-crystallized ligand when possible.
UseAutoDock Vina ↗, Meeko ↗, and PyMOL ↗
If you are new to the terminalAsk a computational colleague to help set up Vina/Meeko once, or work through the official example before using project compounds.
  1. Test your installation with the official example first.

    Follow the official AutoDock Vina “Basic docking” example using the supplied c-Abl/imatinib files. Do not start with a full screening library. Confirm that the example produces a docking output and log without errors.

  2. Choose and inspect the target structure in PyMOL.

    Download the appropriate PDB structure. Check the protein chain, bound ligand, missing regions, cofactors, and waters. Keep the original file unchanged. If a co-crystallized ligand defines the pocket, record its coordinates before removing it from the receptor input.

  3. Prepare receptor and ligand files.

    Use Meeko's receptor-preparation tool to make the receptor PDBQT and create a box around the intended site. Prepare the ligand from an SDF (preferred over PDB for small molecules) with the ligand-preparation tool. Confirm stereochemistry, protonation, and tautomer assumptions before docking.

    mk_prepare_receptor.py -i receptor_with_H.pdb -o receptor -p -v --box_size 20 20 20 --box_center X Y Z
mk_prepare_ligand.py -i ligand.sdf -o ligand.pdbqt

    Replace the example filenames and X/Y/Z values with those for your structure. Box dimensions and centre must be chosen for the target; the values above are placeholders, not universal settings.

  4. Run Vina and preserve the log.

    Use the box configuration generated during receptor preparation. For the first project test, record all settings and use a fixed configuration across analogues.

    vina --receptor receptor.pdbqt --ligand ligand.pdbqt --config receptor.box.txt --exhaustiveness=32 --out ligand_out.pdbqt

    This is a template: the receptor, ligand, and box filenames must match your files. The output contains predicted poses; the log contains scores and run settings.

  5. Validate and inspect before screening more compounds.

    If there is a co-crystallized ligand, redock it and compare the predicted pose with the experimental pose. Open the top poses in PyMOL, check key interactions and clashes, and use PLIP on a properly prepared complex if you need an interaction report. Only move to a larger set after the setup passes its control.

Save as your result

The receptor/ligand input files, box definition, Vina configuration, log, predicted poses, and a validation note describing the control result.

Check before concluding

Docking scores are approximate and should not be read as measured affinities. A plausible pose and a successful control are prerequisites for prioritization, not proof of binding.

Build a practical analogue shortlist

Use known SAR and purchasable-compound data to propose a small set of structures that tests one medicinal chemistry hypothesis at a time.

You needA starting hit or lead, its structure, and the main property or potency limitation you want to improve.
UseChEMBL ↗, DataWarrior ↗, and ZINC ↗
Keep it focusedBegin with 5–20 analogues and one design hypothesis.
  1. Write the design question.

    Choose one priority: improve potency, reduce lipophilicity, improve solubility, explore selectivity, or replace a synthetically difficult group. Record what must remain unchanged, such as a key pharmacophore or core scaffold.

  2. Check existing analogues in ChEMBL.

    Search by compound name or use ChEMBL's structure/similarity search. Review close analogues, their measured activity, and assay provenance before proposing new compounds. Do not compare potency values from incompatible endpoints as if they were equivalent.

  3. Explore the series in DataWarrior.

    Open the structure/activity table, confirm SMILES map to the right IDs, then inspect related structures and property columns. Identify a substituent position to change and keep the rest of the structure constant where possible.

  4. Find available analogues or building-block options.

    Search ZINC for close purchasable analogues or use it to check whether a proposed structure appears in its collections. Save IDs and availability information. A database match is not a guarantee of current stock, purity, or suitability.

  5. Make a synthesis-ready decision table.

    For each candidate, record structure/ID, rationale, expected benefit, key property risk, known activity, availability, and the likely synthetic change. Ask a synthetic chemist to review route plausibility before committing resources.

Save as your result

A ranked analogue matrix with no more than a few clear hypotheses, traceable structures, and an experimental plan.

Check before concluding

Prioritize compounds that are chemically interpretable and practical to make or obtain—not merely those with the best predicted score.
